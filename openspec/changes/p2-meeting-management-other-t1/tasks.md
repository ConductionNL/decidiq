## Deduplication Check (ADR-012)

- [ ] 0.1 Confirm no custom CRUD, search, export, notification, or audit code is introduced: all use `ObjectService`, `CalDavService`, `NotificationService`, `AuditTrailService`, `CnIndexPage`, `CnDetailPage`, `CnFilterBar` from the OpenRegister platform
- [ ] 0.2 Confirm `Meeting` (CalDAV wrapper) and `AgendaItem` entities are used as-is from ADR-000 — no schema properties added or renamed; current-item tracking uses the built-in `status` field; no new X-DECIDESK-* properties beyond the existing `X-DECIDESK-SERIES` from ADR-002
- [ ] 0.3 Confirm `RRULE` extension to `CalDavService` does not duplicate any existing recurrence logic in Nextcloud Calendar app or sabre/dav — search `lib/` for `rrule`, `recurrence`, `RRULE` before implementing
- [ ] 0.4 Confirm speaking time panel is frontend-only (no new PHP service for session state) and `AgendaItem.estimatedDuration` serves as the data source for time limits — no new persistence layer for T1

## 1. Backend — CalDavService RRULE Extension

- [ ] 1.1 Extend `lib/Service/CalDavService.php` — add a `RecurrenceRule` value object (inner class or separate file) with properties: `frequency` (weekly|biweekly|monthly|quarterly), `dayOfWeek` (MO|TU|WE|TH|FR, nullable), `dayOfMonth` (1–31, nullable), `until` (\DateTimeInterface|null), `count` (int|null). Tagged `@spec openspec/changes/p2-meeting-management-other-t1/tasks.md#task-1`.
- [ ] 1.2 Add `buildRRule(RecurrenceRule $rule): string` to `CalDavService` — serializes the `RecurrenceRule` to an RFC 5545 RRULE string (e.g., `FREQ=WEEKLY;BYDAY=TU`, `FREQ=MONTHLY;BYMONTHDAY=15;COUNT=12`). Handle: weekly → `FREQ=WEEKLY;BYDAY={day}`, biweekly → `FREQ=WEEKLY;INTERVAL=2;BYDAY={day}`, monthly → `FREQ=MONTHLY;BYMONTHDAY={day}`, quarterly → `FREQ=MONTHLY;INTERVAL=3`. Tagged `@spec`.
- [ ] 1.3 Add `parseRRule(string $rrule): RecurrenceRule` to `CalDavService` — reverse of `buildRRule`, parses an RFC 5545 RRULE string into a `RecurrenceRule` object for the API response. Tagged `@spec`.
- [ ] 1.4 Extend `CalDavService::createOrUpdateVEvent()` — when the Meeting data array includes a `recurrenceRule` key (non-null `RecurrenceRule`), call `buildRRule()` and add the RRULE property to the sabre/vobject `VCalendar` component; also set `X-DECIDESK-SERIES` from the `series` field. When `recurrenceRule` is null, remove any existing RRULE from the VEVENT.
- [ ] 1.5 Extend `CalDavService::readVEvent()` response — when parsing an ICS blob via sabre/vobject, check for RRULE property; if present, call `parseRRule()` and include the result as `recurrenceRule` in the returned array. If absent, set `recurrenceRule: null`.
- [ ] 1.6 Write PHPUnit tests in `tests/Unit/Service/CalDavServiceRRuleTest.php` tagged `@spec` covering: `buildRRule` weekly → correct FREQ=WEEKLY;BYDAY string; `buildRRule` quarterly with UNTIL → correct FREQ=MONTHLY;INTERVAL=3;UNTIL string; `buildRRule` indefinite → no UNTIL or COUNT; `parseRRule` round-trips correctly; minimum 4 test methods.

## 2. Backend — MeetingController Extension

- [ ] 2.1 Add `live(string $id): JSONResponse` method to `lib/Controller/MeetingController.php` tagged `@spec openspec/changes/p2-meeting-management-other-t1/tasks.md#task-2`. Annotate with `#[PublicPage]` and `#[NoCSRFRequired]`. Reads Meeting via `ObjectService.findObject()` and CalDAV VEVENT via `CalDavService`. Returns only safe public fields: `{ title, lifecycle, meetingMode, location, scheduledDate, currentAgendaItem }`. Derives `currentAgendaItem` by calling `ObjectService.findAll()` on AgendaItem with filter `{ status: 'current' }` and returning the first result's `{ title, orderNumber, estimatedDuration }`. Returns HTTP 404 with `{ "message": "Meeting not found" }` if the id is unknown.
- [ ] 2.2 Add `setCurrentAgendaItem(string $id, string $itemId): JSONResponse` method to `MeetingController` tagged `@spec`. Requires `#[NoAdminRequired]`. Verifies the requesting user has role `chair` or `secretary` in the GovernanceBody linked to the Meeting via `AuthorizationService`. Finds any existing AgendaItem with `status: current` for this meeting and sets it to `upcoming`. Sets the target AgendaItem `status` to `current` via `ObjectService.saveObject()`. Returns HTTP 200 with the updated AgendaItem, or HTTP 403 if the user lacks the required role, or HTTP 404 if the AgendaItem is not found.
- [ ] 2.3 Register both routes in `appinfo/routes.php` — specific routes BEFORE any wildcard `{slug}` routes:
  - `GET /api/meetings/{id}/live` → `meeting#live`
  - `POST /api/meetings/{id}/agenda-items/{itemId}/set-current` → `meeting#setCurrentAgendaItem`
- [ ] 2.4 Write PHPUnit tests in `tests/Unit/Controller/MeetingControllerExtTest.php` tagged `@spec` covering: `live()` returns public data for a known meeting; `live()` returns HTTP 404 for unknown id; `live()` response does not contain attendee list or internal notes; `setCurrentAgendaItem()` clears previous current item and sets new one; `setCurrentAgendaItem()` returns HTTP 403 for non-chair/secretary role; minimum 5 test methods.
