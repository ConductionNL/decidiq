## 3. Budget proposals + advisory voting (reuse voting machinery)
- [x] 3.1 Proposal submission: authenticated create during `submission` phase with server-side `requestedAmount` validation (positive, ≤ `totalAmount`); staff validation transition `submitted→validated|rejected`.
- [x] 3.2 Extend the voting tally machinery with advisory mode: `VotingService::applyAdvisoryTally()` + `tallyAdvisoryProposal()` reuse the statutory `filterByRelation()` dedup path and the deterministic-`@self.slug` atomic-upsert; no parallel tally implementation; no quorum, no secret ballot, no proxy, voor/tegen only.
- [x] 3.3 Vote endpoint: one `CitizenVote` per authenticated citizen per `validated` proposal, conflict on duplicate, closed outside the `voting` window, tallies written atomically to `votesFor`/`votesAgainst`.
- [x] 3.4 Result calculation: `BudgetVotingService::calculateAllocation()` ranks by `votesFor` with greedy allocation within `totalAmount`, marking proposals awarded/not-funded; advisory results never feed statutory decision outcomes.
